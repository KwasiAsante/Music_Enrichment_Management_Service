▸ Workflow Guide

The full path from "no files yet" to "fully tagged" — six pages, in order. Click a stage to jump to its detail below.

♪ 0. Find & Download Music Search optional → ◆ 1. Scan Dashboard → ⚭ 2. Review Mappings → ⚭ 3. Map / Skip / Exclude Mappings → ▶ 4. Enrich Enrich → ▤ 5. Verify Library
  1. 0
    Find & download albums optional Music Search →

    Skip this step if you already have the files — it's only for building out your library from scratch. Search MusicBrainz for a release, then use the Prowlarr/Nyaa tab to find and send a download to qBittorrent, which drops it into your configured save path.

    → This is a separate flow from the rest of the app (see the Music Search section below) — once files land on disk, step 1 (Scan) is what actually notices them.

  2. 1
    Add albums to the library Dashboard →

    Click Scan Library to walk your music folders and build (or refresh) the album list — this is what every other page reads from, so it's the real starting point whether your files just arrived via step 0 or were already there. Tick also remove empty folders if you also want a cleanup pass for folders with no audio in them; it's opt-in because it deletes folders.

    → New albums immediately show up in the stat cards, and any that need a VGMDB match land in Mappings' Unmapped list.

  3. 2
    Review what needs mapping Mappings →

    Open the Unmapped Albums list — every album scanned in step 1 that has no VGMDB association yet. Use the Artist filter to work through one artist's backlog at a time instead of the whole list at once.

    → Each row is a decision point — which one you pick depends on what the album actually is (see step 3).

  4. 3
    Map, skip, or exclude Mappings →

    For each unmapped album, pick one of three paths:

    • It's on VGMDB — click Search, review the candidates, click Set on the right one.
    • It genuinely isn't on VGMDB — click Skip. It moves to the Skipped Albums panel and won't be asked about again (restore it any time if you change your mind).
    • The whole artist will never be on VGMDB (Western acts, etc.) — add them once to Excluded Artists instead of skipping every one of their albums individually. This also keeps bulk enrichment from wasting time on them.

    → Worth doing before a big session: Export a mapping backup from the Backup & Restore panel — these decisions take real effort to build.

  5. 4
    Run enrichment Enrich →

    Once mappings look right, start a run — leave the artist/album filters blank to run against everything, or scope to just what you mapped this session. Try Dry run first if you want to preview matches before anything gets written to your files.

    → Watch the live progress bar and log while it runs; Recent Enrich Activity below keeps a history once it's done.

  6. 5
    Verify the results Library →

    Switch the View filter to Enriched to confirm the albums you just ran actually got tagged. Anything still Unmapped needs another pass through steps 2–3; anything in the Skipped view was a low-confidence auto-match beets declined to guess at — those usually need a manual Search & Set back on Mappings instead.

    → Once your library's in good shape, try Group by artist with the grid layout for a nicer browsing view with cover art.

From here it loops: new albums keep landing via Scan, so steps 2–5 repeat naturally as your library grows.

◆ Dashboard

The at-a-glance overview — library health, quick actions, and recent activity.

  • Stat cards (Total / Enriched / Unmapped / Skipped) are clickable — each jumps straight to Library pre-filtered to that view.
  • Scan Library rebuilds the album list from what's actually on disk. Tick also remove empty folders to also delete album/artist folders with no files or no audio — this is destructive, so it's opt-in.
  • Fix Artist Paths normalizes artist folder names (e.g. kanji → romanized) where that's been configured.
  • Run Enrichment is a shortcut straight to the Enrich page.
  • Recent Activity shows the latest log entries across every category, filterable by category — the same underlying log as the full Logs page, just the tail end of it.

⚭ Mappings

Where an album's MusicBrainz release id gets tied to its VGMDB id — the core data this whole app is built around.

  • Unmapped Albums lists every album with no VGMDB association yet. Search runs the same lookup pipeline enrichment uses (catalog number, barcode, title); Set saves whichever result you pick.
  • Skip (on an unmapped album) marks it vgmdb_id: "skip" — "confirmed, not on VGMDB, stop asking." It moves into the Skipped Albums panel below, where Restore undoes it and puts the album back into Unmapped.
  • Excluded Artists is a broader tool than Skip — it's a whole artist (Western acts with no VGMDB presence, etc.), not one album. An excluded artist's albums disappear from Unmapped and get skipped automatically during bulk enrichment, so you don't have to Skip every one of their albums individually. Add or remove artists from the panel any time; removing one puts their albums back into consideration immediately.
  • Backup & Restore exports the entire mapping file as a timestamped JSON download, or restores/merges one back in. Merge adds/overwrites on top of what you have; Replace wipes the mapping first and uses only what's in the file — a confirmation prompt guards against doing that by accident.

▶ Enrich

Runs the bulk tagging pass that writes resolved VGMDB metadata into your audio files.

  • Artist filter / Album filter scope a run to specific names (comma-separated); leave blank to run against everything.
  • Redo (specific albums) forces a re-run on named albums even if they were already processed — useful after fixing a mapping.
  • Redo skipped re-attempts albums that were previously left untagged for low match confidence (see the Library page's Skipped view) instead of leaving them alone.
  • Dry run reports what the run would do — matches found, tags that would change — without writing anything to disk. Good for sanity-checking filters before a real run.
  • Progress (a live badge, count, and log) shows while a run is in flight; Recent Enrich Activity below keeps a history of past runs.

▤ Library

Browse every album that's been scanned, with its current status.

  • Filters: Artist and Folder are substring matches; View switches between All / Unmapped / Enriched / Skipped; Mapped via narrows by how a mapping was made — Manual (set by hand on the Mappings page), Auto-matched (resolved automatically during a search or enrichment run), or Imported (restored from a backup file).
  • Group by artist buckets results under artist headers instead of a flat list. Click a header to collapse/expand it, or use Collapse all / Expand all in the toolbar. Not paginated — it fetches everything matching your filters, capped at 2000 albums (you'll see a note if a filter set is broader than that).
  • List / Grid layout — grid mode shows a square cover-art thumbnail per album, pulled from a cover image file in the album folder (cover.jpg, folder.png, etc.) or whatever's embedded in the first audio file. An album with neither just shows a plain placeholder — that's expected, not an error.
  • The Skipped view here is not the same thing as Mappings' Skipped Albums panel — see the FAQ below for the distinction, it trips people up.

≡ Logs

The full activity history — every scan, mapping change, enrichment run, and error, in one filterable feed.

  • Filter by Category (scan, mapping, enrich, etc.), Level (info/warning/error), or an exact Artist name.
  • Refresh pulls the latest entries — the page doesn't auto-poll, so use it after kicking off something elsewhere.

♪ Music Search

A standalone downloader flow, separate from the mapping/enrichment pipeline above: MusicBrainz → Lidarr → Prowlarr/Nyaa → qBittorrent.

  • ① MusicBrainz Search — find a release by name, filter by type (Album/Single/EP/Soundtrack/Compilation).
  • ② Prowlarr / Nyaa Search — once you've picked a release, search indexers for a download and send it to qBittorrent.
  • Music Save Path controls where qBittorrent saves finished downloads. Lidarr/Prowlarr/qBittorrent credentials themselves are configured server-side (.env) — nothing sensitive lives on this page or in your browser.

? FAQ & Troubleshooting

What's the difference between "Skipped" on the Library page and "Skipped Albums" on the Mappings page?
They're unrelated, despite the name. Mappings → Skipped Albums is albums you explicitly marked "not on VGMDB, stop asking" — a manual decision. Library → Skipped view is albums where enrichment found a VGMDB candidate but its match confidence was below the configured threshold, so it declined to auto-tag rather than guess — an automatic, low-confidence outcome. An album can show up in one without ever touching the other.
An artist I expect to see isn't showing up in Unmapped. Where did they go?
Check Mappings → Excluded Artists — if the artist is on that list, their albums are deliberately left out of Unmapped (and skipped by bulk enrichment). Remove them from the list to bring their albums back into consideration.
Grid view shows a placeholder instead of cover art for some albums.
The app looks for a cover-image file in the album folder first (cover.jpg, folder.png, front.jpg, albumart.png, etc.), then falls back to whatever's embedded in the first audio file. If neither exists, there's simply no art to show — add a cover file to the folder, or embed art in the audio files, and it'll pick it up. Note: embedded art in .ape files specifically isn't supported.
How do I back up my VGMDB mappings before trying something risky?
Mappings page → Backup & Restore → Export backup. It downloads the full mapping as a timestamped JSON file. If something goes wrong later, restore it from the same panel — Merge is the safe option; Replace wipes the current mapping first, so use it deliberately.
I dismissed a tip banner and want it back.
Tip dismissals are remembered per-browser, not server-side. Clearing this site's data in your browser (or opening the app in a private window) will bring every tip back.
Something looks wrong and I'm not sure why.
The Logs page has a full, filterable history of everything the app has done — scans, mapping changes, enrichment runs, and any errors along the way. It's usually the fastest way to see what actually happened.
